One engine for every icon

The goal: every icon is created, sized, placed, bordered and highlighted by the same code, so no icon can round a pixel differently from its neighbour. This page lists what exists today, where icons drift apart, and the order I recommend for unifying them.

Audited at commit 85494b6 · 30 Oct 2026 · no files changed by the audit

Verdict

Shared building blocks exist, but only some icons use them. The rest create and place themselves, which is how the 1-pixel differences keep appearing.

Where they differ

Anchoring

  • Placer: top-left corner, rounded to a whole pixel.
  • Icons inside aura groups and kicker sections: the group's corner, not rounded.
  • Cast icon: top-left or top-right of the plate when spanning, otherwise left or right of the bar.
  • Live aura containers: the group's corner on the plate, not rounded.

Offset maths

  • Three sign systems: the position table, the aura grow direction, and hand-written gap / -gap on the cast icon.
  • Only live auras multiply by the aura scale factor; the preview icons do not.

Parent and level

  • Overlay +0: preview aura groups, elite, quest, faction.
  • Overlay +1: live aura containers.
  • Overlay +5: kicker holder, raid marker layer.
  • Cast bar level: spell icon.

Size, border, crop

  • Whole pixels only for auras and kickers.
  • Two border systems: the icon ring and the four-sided bar border.
  • Crop: fixed for auras, per picture style for kickers, a setting for the cast icon, never for glyphs.

Text on icons

  • Auras: Plateau's own timer and stack text, placed by one helper.
  • Kickers: Blizzard's built-in countdown number, re-centred by hand.

Updates and scale changes

  • Auras redraw on scale change through their own hook; the cast bar has another.
  • Kickers rely on their borders' registration.
  • Glyph icons never redraw on scale change.

Recommended plan

Ordered so each step is safe on its own and the riskiest step, renaming saved settings, comes last and is optional. Steps 1–5 change no saved settings.

  1. One icon builder for every icon

    Low risk

    Build the cast icon, raid marker, elite, quest and faction icons with the same builder the auras and kickers use. Glyph icons get the builder's border turned off. Every icon then has the same picture texture, border, rounding and hover/selected highlight.

  2. One sizing rule

    Low risk

    Route every icon size through the whole-pixel helper: glyph sizes, the cast icon's bar height, and class-resource pip width and spacing. Apply the aura scale factor in the preview as well, so the preview matches live plates.

  3. One placement routine, including inside groups

    Medium risk

    Add one grid helper on top of the placer so icons inside aura groups, kicker sections and class-resource pips are placed by the same top-left, whole-pixel rule as everything else. Convert the cast icon's two branches into placer calls. Give the faction icon's name-only mode a placer call anchored to the name.

  4. One text rule on icons

    Low risk

    Use Plateau's own countdown text on kicker icons, placed by the same helper as aura timers, instead of Blizzard's number. Timers and stacks then sit identically on every icon.

  5. One table of frame levels and one scale-change hook

    Low risk

    Name the layer each icon type sits on in one place, and register every icon with one scale-change redraw so glyph icons stop going stale after a scale change.

  6. One settings shape (optional)

    High risk

    First read every icon's settings through one adapter that turns each element's own keys into a common shape (size, border, crop, placement). Rename the saved keys only if you want the options pages unified too. That needs a profile migration.

Leave as is

  • Blizzard creates the live aura buttons and lays them out in its aura container. Plateau can decorate them but not build or place them.
  • Blizzard sizes the live aura containers as auras come and go, so they keep their corner anchor. That corner already lands on a whole pixel.
  • Class-resource pips stay status bars. Only their size and placement move to the shared code.
  • The cast icon keeps the option to span the plate and the bar. The span becomes an input to the placer rather than its own branch.

Risks

Real differences

  • Multi-icon grids with growth direction (auras).
  • Clipped kicker sections that open by raid-marker value.
  • A cast icon sized from the bar that can span two frames.
  • Atlas glyphs that may not be square.

Accidental differences

  • Direct SetPoint against the placer.
  • Rounded against unrounded sizes.
  • Frame levels.
  • Missing aura scale in the preview.
  • Two border systems on icons.
  • Two kinds of countdown text.

Blizzard restrictions and combat

  • Live aura buttons are restricted: no Lua functions stored on them and no nil passed to their setters.
  • Restyling waits while Blizzard's restriction is active.
  • Sizes and scales can be hidden values in combat, so the placer must keep its guards.
  • Plateau's own plate frames aren't secure, so there's no taint risk there.

Saved settings

  • Auras use side / align / grow.
  • Other icons use position / gap.
  • The cast icon uses iconSide / iconSpan.
  • Renaming means migrating every profile, Default included.
  • The defaults, the options rows and the drag-snap code would all have to change together.

Your decisions

Cast-icon border

Match the cast bar's border style (today), or use the same icon border as auras and kickers?

Kicker countdown

Switch to Plateau's own timer text like the auras (recommended), or keep Blizzard's number?

Saved settings

Stop at the adapter in step 6 (no migration), or rename the keys and migrate profiles?

Where to start

Steps 1–2 together are the smallest change that puts every icon on the same builder and sizing.
